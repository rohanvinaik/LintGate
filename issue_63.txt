## Goal
Introduce **strategy-scoped mapping diagnostics plumbing** so mapping outcomes are attributable to specific resolution paths.

## Implementation guidance
1. Add strategy diagnostics primitives in `lintgate/linters/test_effectiveness/types.py`.
- Add `StrategyDiagnostics` dataclass with at least:
  - `strategy`
  - `attempted`, `matched`
  - `dropped_ambiguous`, `dropped_no_candidate`, `dropped_shadowed`
- Extend `MappingDiagnostics` with additive field:
  - `strategy_breakdown: dict[str, StrategyDiagnostics]`
- Keep existing fields (`attempted`, `mapped`, `dropped_*`) unchanged for backward compatibility.

2. Thread strategy labels through mapper resolution in `lintgate/linters/test_effectiveness/source_mapper.py`.
- Extend `_try_add_match(...)` to accept `strategy: str`.
- Pass explicit strategy labels from callers:
  - call graph path: `"call_graph"`
  - naming path: `"naming"`
  - alias/import symbol path: `"alias_import"` (or documented equivalent)
- Update diagnostics so each attempt/match/drop updates both:
  - aggregate counters (existing behavior)
  - strategy-scoped counters (new behavior)

3. Keep serialization additive.
- `MappingDiagnostics.to_dict()` must include new keys additively.
- Existing consumers reading old keys should continue to work unchanged.

## Test guidance
Add/update tests in `tests/test_source_mapper.py`:
- `test_diagnostics_strategy_breakdown_call_graph`
- `test_diagnostics_strategy_breakdown_naming`
- backward-compat serialization assertion: old keys remain present/correct.

## Acceptance criteria
- Strategy-level counters are emitted and non-empty on mixed mapping fixtures.
- Aggregate counters still match prior behavior.
- No breaking changes to existing serialized keys.
