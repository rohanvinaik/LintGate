## Scope
Phase 1 foundational work for normalized mapper diagnostics.

## Dependency placement
- Phase: **1**
- Parallel with: #63
- Supports: #56
- Depends on: none (can build on #63 data model if landed first)

## Goal
Add **normalized and deduplicated diagnostics** so hinting logic is based on meaningful rates, not only raw attempt counts.

## Implementation guidance
1. Extend `MappingDiagnostics` in `lintgate/linters/test_effectiveness/types.py` with additive fields:
- `unique_symbols_attempted` (derived from internal set length)
- `unique_symbols_mapped` (derived from internal set length)
- `test_functions_examined`
- `top_drop_examples` (top-N entries `{symbol, reason, strategy}`)
- `dominant_drop_reason`
- `dominant_drop_pct`

2. Track non-serialized internal state safely.
- Use internal sets/lists with `field(default_factory=...)` for unique tracking.
- Do not serialize raw set objects; only expose derived scalar/list outputs.

3. Compute normalized diagnostics in mapper flow.
- In `map_tests_to_source`, update test-function examined count.
- Track unique attempted/mapped symbols.
- Record drop examples and truncate to top 5.
- Compute dominant drop reason and pct over total drops.

4. Document semantics.
- Clarify in code/docs that strategy attempt sums may exceed aggregate test-function attempts due multi-strategy evaluation.

## Test guidance
Add/update tests in `tests/test_source_mapper.py`:
- `test_diagnostics_unique_symbol_counts`
- `test_diagnostics_top_drop_examples`
- `test_diagnostics_dominant_drop_reason`
- `test_diagnostics_normalized_vs_raw` (`unique_symbols_attempted <= attempted` invariant or documented alternative metric relation)

## Acceptance criteria
- Diagnostics include both raw and normalized fields.
- Dominant reason and pct are present when drops exist.
- Serialization remains backward compatible.
